# Kapy control SPA

Mobile-first Provider, Model and Session configuration. There is no chat, runner,
queue, history or live UI. Vue 3, Vue Router, TypeScript and Vite were initialized
with official `create-vue@3.23.0 --ts --router --vitest --playwright --eslint --bare`.
The scaffold's conflicting redundant Oxlint integration and devtools were removed;
ESLint checks handwritten source. Reka UI owns confirmation-dialog focus/keyboard
behavior. Native CSS tokens flow primitive → semantic → component.

Use Node 24 LTS (verified with 24.21.0) and npm 12 (verified with 12.0.2);
package-lock.json locks dependencies. The generator pins an older js-yaml; a
compatible 4.3.2 override includes its CPU-exhaustion fixes.

```sh
cd frontend
npm ci
npm run dev                 # /app/, /api proxy defaults to 127.0.0.1:8000
npm run type-check
npm run lint
npm run test:unit -- --run
npm run build               # includes vue-tsc; needs no API/database
npm run preview
```

`API_PROXY_TARGET` overrides the development proxy. Browser requests always use
same-origin credentials and the generated `/api` paths. API keys stay in form
memory and clear after success. The standalone HTTP plugin requires no access token.

## API generation

The committed SDK was generated by `@hey-api/openapi-ts@0.99.0` from the actual
local FastAPI `/openapi.json` at backend commit
`d0da28e6d9c2e8c65de006128bd065d5fdfa3db2`, with this branch's readable
`ProviderRecord.provider_kwargs` addition. No provisional schema or handwritten
API DTOs are retained. Only TypeScript, SDK and Fetch plugins are enabled.

```sh
npm run api:generate
# Or target the configured API host:
OPENAPI_URL=http://127.0.0.1:8001/openapi.json npm run api:generate
```

Regenerate after backend contract changes; never edit `src/api/generated/`.
Normal build uses these committed files without contacting the API.

## Hosting

The independent HTTP plugin can mount the existing build alongside `/api`:

```sh
kapy plugin http serve --frontend-dist /absolute/path/to/frontend/dist
```

`KAPY_HTTP_FRONTEND_DIST` provides the same setting. The frontend and HTTP/WS API
are directly accessible without login or an access token. The SPA uses
same-origin requests.

```python
from kapy.tmpv2.plugins.http import create_frontend_router, create_router

app.include_router(create_router(models, sessions, agent=agent))
app.include_router(create_frontend_router(frontend_dist_dir))
```

The host supplies an explicit path to the Vite `dist/` directory and retains its
existing lifespan. Missing index.html fails setup. FastAPI's native frontend
fallback serves `/app/...` navigation; missing assets stay 404. API-only hosts
can omit the frontend router. Build outputs and tool caches are ignored.

## Deterministic browser checks

Start `npm run dev -- --host 127.0.0.1 --port 5173 --strictPort`, then:

```sh
npx playwright install chromium
npm run test:e2e
```

Contract fixtures test both mobile and desktop Chromium. They cover PATCH bodies,
slash model names, pagination, JSON errors, 422/409/500 responses and dialog focus.
Unit tests cover GET cancellation and stale-response rejection.

For actual FastAPI/PostgreSQL browser integration, build first, then from the repo:

```sh
.venv/bin/uvicorn test_api:app --app-dir frontend/scripts --host 127.0.0.1 --port 8001
# In frontend/, while both test API and Vite are running:
KAPY_SPA_INTEGRATION=1 npm run test:e2e
```

`test_api.py` uses the existing local test PostgreSQL on 55432, owns a random
`spa_test_*` schema and drops it on graceful shutdown. It never reads `.env`.
Tests create only configuration with fake keys and explicit model capacities;
they make no model requests or discovery calls. Reports are in playwright-report/
and test-results/. Backend tests are `tests/tmpv2/agent_runner/test_frontend.py`.
